# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An HTTP server that makes local [Laya](https://github.com/NandhaKishorM/laya) checkpoints a
drop-in replacement for [TypeSafe's Jev API](https://docs.typesafe.ai/api). A client sets
`TYPESAFE_BASE_URL` to this server and needs no other change. See `README.md` for the API surface
and the known divergences from Jev.

## Commands

`make help` lists everything. The common ones:

```bash
make install
make dev                        # first start downloads ~843MB per checkpoint
make test                       # fast suite: stubs Laya, no network, <1s
make test-slow                  # loads a real checkpoint (~20s)
make lint                       # ruff check + format check
make typecheck                  # mypy, strict, over src/
make zizmor                     # security audit of .github/ (workflows + dependabot.yml)
make format                     # apply autofixes and reformat
make ci                         # what CI runs: lockfile check + lint + types + zizmor + fast suite
uv run pytest tests/test_engine.py::TestConcurrency   # a single test target
```

`make ci` mirrors `.github/workflows/tests.yml`; keep them in step when either changes.
Workflow edits must stay zizmor-clean: pin new actions to a full commit SHA with a `# vX.Y.Z`
comment, keep `permissions` read-only, set `persist-credentials: false` on checkout, and pass
`${{ }}` values to scripts through `env:` rather than expanding them inline.

The README's table of contents is generated by `scripts/toc.py`. Rename a heading and `make lint`
fails until `make toc` regenerates it, so the anchors cannot silently rot.

`make docker-build` / `make docker-run` build and run the container. The Dockerfile installs
CPU-only torch by exporting the locked versions, dropping the GPU-only packages
(`nvidia-*`, `triton`, `cuda-*`) and installing with `uv pip install --torch-backend=cpu` —
`uv sync` has no such flag and silently ignores `UV_TORCH_BACKEND`. That filter is what keeps
the image at ~1.6GB instead of ~2.7GB; triton alone is 813MB of GPU kernel compiler.

`make docker-push` publishes multi-arch to Docker Hub under `NAMESPACE` (default `pambrose`),
tagged with the `pyproject.toml` version and `latest`. It confirms before pushing. Version
bumps come from `pyproject.toml`; the Makefile reads it, so there is no second place to edit.

## Architecture

Request flow through `src/laya_server/`:

```
app.py      auth -> schema validation -> engine -> Jev-shaped JSON + X-Laya-Checkpoint
engine.py   validate questions -> resolve model -> keep Jev fields -> route -> validate budget -> lock -> threadpool
translate.py  Laya answer dict -> Jev answer dict
```

The two non-obvious constraints that shape all of it:

**Laya's validation is not Jev's.** laya 0.3.4 validated nothing, and malformed input became a
raw `KeyError`/`AttributeError`/numpy error — a client-triggerable 500. Since 0.4 it checks each
question itself (`Agent._check_question`) and raises `ValueError`, but its rules are not Jev's:
it accepts what Jev's limits reject (256 options, 1 or 11 score levels) and honors fields Jev does
not have (`labels`, `option_order`). `validation.py` therefore applies Jev's rules first, then
calls laya's own check, so every malformed question is a 422 before tokenizing. It calls laya's
private static helpers (`_check_question`, `_to_internal`) rather than mirroring them, because the
mirror drifted silently on the 0.3.4 -> 0.4.1 upgrade. Only `type`, `instructions` and `criteria`
reach laya (`jev_questions`). If you add a question field, add its validation there first.

**One owner for the Router.** laya 0.4 locks the Router's lifecycle and makes inference re-entrant,
which 0.3.4 did not. `engine.py` is still the only place allowed to touch the Router, and its
choices are now policy rather than protection: it preloads every checkpoint and sizes `max_loaded`
to cover all of them so nothing is rebuilt mid-traffic, holds one `asyncio.Lock` per checkpoint so
one checkpoint's requests run one at a time (bounding CPU threads and GPU memory, and giving the
queue-depth limit something to count), and offloads routing, budget checks and the forward pass.
Routing happens *outside* the lock because `Router.route` is pure — that is what lets different
checkpoints run concurrently. It always passes `default=` explicitly: laya 0.4 moved its fallback
for undecided language from `english` to `multilingual`. Any direct tokenizer call must go through
`laya.common.encode_text`, which holds laya's tokenizer lock; laya now mutates the shared fast
tokenizer (truncation settings) while encoding.

## Conventions

- The response body must contain exactly `model`, `answers`, `usage` — nothing Jev would not send.
  Laya's extra `action` blocks and `answer_confidence`, its noul `confidence`, every `usage` key
  but `input_tokens`/`output_tokens`, and the `routing` key are stripped in `translate.py`, which
  also echoes object/array score levels in `legend` as the caller wrote them (laya renders them to
  JSON text). Server-specific data goes in a header instead (`X-Laya-Checkpoint`).
- Wire-shape changes need a matching case in `tests/test_sdk_compat.py`, which parses our output
  with TypeSafe's real `SystemOneResponse` model. Note the SDK ignores unknown keys, so that suite
  proves parseability, not exactness — `test_translate.py` covers exactness.
- The fast suite must never download a checkpoint. Use the fakes in `tests/conftest.py`.
- Warnings are errors (`filterwarnings = ["error", ...]` in `pyproject.toml`), so a new
  deprecation fails the suite rather than scrolling past. Silence one only with a message-specific
  `ignore:` entry plus a comment saying what to upgrade to and when the entry can go — never a
  blanket `ignore::DeprecationWarning`.
- `TestClient` needs `httpx2`; with plain `httpx` starlette emits a deprecation that, under the
  rule above, fails the build. `httpx2` is therefore an explicit dev dependency rather than
  something inherited from `typesafe-sdk`.
- Ruff's rule selection is pinned explicitly in `pyproject.toml` rather than inherited, because
  ruff's defaults shift between releases and CI must lint what a developer's machine does.
  Linting covers `src/`, `tests/` and `scripts/`.
- mypy runs `--strict` but only over `src/`, because `py.typed` publishes those signatures to
  consumers. Tests and scripts are not shipped and are not type-checked; adding them would be
  ~170 mostly-cosmetic errors. Keep `src/` strict-clean — it is what the marker promises.
- `docs/code-review.md` tracks known issues as numbered checkboxes. When you fix one, tick its
  box, flip its **Status** to `fixed`, and update the counts in the header line. Never renumber
  existing items — the numbers are referenced elsewhere.
- Update `CHANGELOG.md` alongside user-visible changes. The version lives only in
  `pyproject.toml`; the Makefile and Docker tags read it from there.
- Laya reports device downgrades and OOM fallbacks as `RuntimeWarning`s on stderr, never through
  `logging`, so a `cuda -> cpu` downgrade will not appear in structured logs. It also warns on
  every load of `english` and `typed-decisions` that it clamped their `choice:11+` temperature;
  the suite ignores exactly that message (`pyproject.toml`).

## Reading the library

`laya` has no online API docs. Read the installed source at
`.venv/lib/python3.12/site-packages/laya/` (`router.py`, `agent.py`, `common.py`, `presets.py`,
`confidence.py`) rather than guessing. Line numbers cited in `src/` and `tests/` are to laya 0.4.1.
Note the yes/no primitive is spelled `noul` — it looks like a typo and is not.

`docs/running-laya-outside-python.md` already documents the model itself: a ModernBERT encoder
plus a custom decision head, the `[MASK]`-marker sequence layout that lets one forward pass answer
a whole schema, the per-checkpoint length budgets, and a verified ONNX export (`scripts/`). Read
it before re-deriving any of that from the library source.

The one thing in there worth knowing up front: scoring is scaled by `temperature_by_options`, a
per-checkpoint lookup keyed `"<type>:<bucket>"`, and the flat `temperature` list is only the
fallback. `typed-decisions` has near-neutral base temperatures but inherits `english`'s full
table, so reading only the list gives plausible but wrong probabilities. Since 0.4 laya clamps
every value into `[0.5, 5.0]` at load, so the shipped `choice:11+` of 0.1006 is applied as 0.5.
